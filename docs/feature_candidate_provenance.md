# Feature-candidate provenance

The formal benchmark performs variance-based feature selection inside each held-out fold, using training rows only. The prepared input tables contain a fixed 2,000-feature candidate set per modality. These candidate tables were generated by the training-only selector in `scripts/select_features_train_only.py` from declared training cell-line IDs; they are not response-selected feature lists.

The formal runners therefore provide fold-local selection within the locked candidate universe. This is leakage-controlled with respect to held-out responses and datasets, but it is not equivalent to selecting from the complete raw feature universe inside every formal fold. Future reruns should preserve the candidate-table source IDs and, preferably, perform fold-local ranking from the full raw feature matrices.

The candidate tables are ignored by Git because of their size. Reproducibility requires the raw provider files, the training-ID manifests, the selector command, and the release checksums recorded in the project environment.
